## What "the examples" actually are

- 26 styles, one demo page each, in `skills/awesome-page-design/assets/styles/style-XX-*/style-XX-*.html` + desktop PNG (1440×1200) + mobile PNG (390×844).
- Those HTML/PNG files are **generated outputs, not source**. Do not edit them directly — `npm run previews` regenerates them and `asset-manifest.json` (SHA-256) will then fail validation.
- Source of truth is `catalog/styles.json` (194 KB, 26 styles: tokens + `scenario` + `playbook` + `geometry` + `implementation` + `notes`).
- Page source lives in two generations:
  - **01–02, legacy:** `scripts/preview-page-renderer.js` → `renderDistinctStyleHtml()`, using the 8,186-line `scripts/preview-pages/shared.css` plus `style01-inventory.js/css` and `style02-market.js/css`. Generated HTML is 268 KB (01) and 240 KB (02).
  - **03–26, redesigned:** `scripts/preview-pages/redesign/styleXX.js` + `styleXX.css` (JS 7–13 KB, CSS 5–18 KB each), rendered by `renderRedesignedHtml()` with `redesign/base.css` (2 KB), `redesign/runtime.js`, and a toolbar CSS slice extracted from `shared.css`. Generated HTML is 47–71 KB each.
- Every page shares the same preview chrome: dark `.preview-context-shell` bar (`#232529`, style number + Chinese name, “风格库 / 选用此风格”), plus the same dialog/toast/form runtime. The gallery is `skills/awesome-page-design/assets/previews/index.html` (903 KB), generated by `scripts/preview-gallery.js` + `preview-pages/gallery.css` (655 lines).
- Verification chain: `npm test` → `npm run validate` / `npm run check`; `scripts/generate-previews.js` publishes transactionally with rollback; screenshots wait 5 s per page in headless Chrome.

## Why they read as "ugly" — 5 systemic causes, verified

1. **No real imagery at all.** 0 `<img>` tags in all 26 generated pages. No `@font-face`, no Google Fonts, no Unsplash/Picsum/CDN images anywhere in `scripts/` or `references/`. Every visual is a CSS shape or inline SVG (01 has 43 SVGs, most others 3–22). Posters, photos, maps and product shots are all flat coloured blocks, so pages feel like wireframes, not finished sites.
2. **One font stack everywhere.** Redesigned pages all use `"PingFang SC", "Microsoft YaHei", ui-sans-serif, system-ui, sans-serif`; display type is only Georgia / Courier New in a few places. No display/serif/mono pairing per style, no type scale discipline — the main thing separating “Swiss Editorial” from “Tech Minimal” is often just the token colours.
3. **The same preview chrome flattens every style.** The dark toolbar sits on top of light, pastel, brutalist and ink-wash pages alike. It makes the gallery feel like one tool, and it eats the first ~48 px of every screenshot.
4. **Two generations, inconsistent quality.** 01/02 are dense, functional, and actually the most “real” (01 is a working inventory table); 03–26 are cleaner but thinner — most follow the same hero + configurator/form + 3-step strip pattern, with invented micro-businesses as content.
5. **Thin, invented content + dead space.** Scenarios are fictional small shops (see table below), copy mixes Chinese headlines with English eyebrows, and “本地模拟 · 没有向外部发送数据” notes appear everywhere. At the fixed 1440×1200 screenshot size, several pages (01, 18) leave a large empty band at the bottom.

None of this is a reason to throw the Skill away: `SKILL.md`, `references/workflow.md`, the component contracts, prompts and validation are the valuable part. The redesign target is the **example layer only**.

## Proposed redesign system (to agree before building)

**Keep:** style names/IDs/slugs, `catalog/styles.json` schema, Skill workflow + references, prompt generation, validation/tests. Renaming IDs breaks prompts, gallery deep links (`?style=09#style-09`) and the manifest.

**Change — shared layer first:**
- Typography: one deliberate pairing per style family (display / text / mono), still offline-capable — either self-hosted subsets in the repo or disciplined system stacks with distinct fallbacks. No Google Fonts CDN unless we drop the offline-gallery promise.
- Imagery: a single rule for all 26 — either (a) a local SVG illustration/photo system checked into `assets/`, or (b) CSS/SVG art done properly with a shared motif library. No external hotlinks.
- Preview chrome: lighter, collapsible, style-aware (not the same dark bar on every page); gallery cards redesigned at the same time.
- Layout: retire the repeated hero + form + 3-step strip where it does not fit the scenario; each style gets a layout true to its `bestFor` (table, pipeline graph, configurator, reader, map, player…).
- Content: keep the 26 fictional brands or replace them with tighter, more believable scenarios — decision needed. Either way, remove repeated “本地模拟” noise from the visual hierarchy.

**Change — per style:** `catalog/styles.json` tokens + `scenario` + `notes`, `scripts/preview-pages/redesign/styleXX.js/css`, and for 01/02 the legacy `style01-inventory.*` / `style02-market.*` + `shared.css` slice. Then `npm run docs`, `npm run previews`, `npm run check`.
