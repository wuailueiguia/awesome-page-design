# 避免模板化 UI

页面缺少产品特点、层级混乱或明显沿用默认样式时，按下面的问题寻找原因。命中某种视觉形式只代表需要判断，不自动构成缺陷；修正应服务于真实任务和已选风格。执行顺序与范围见[工作流程](workflow.md)。

## 结构与信息层级

| 看到的现象 | 先判断什么 | 优先修正方向 |
|---|---|---|
| Hero、三个功能 Card、指标条和结尾行动入口反复出现 | 用户实际需要浏览叙事、操作数据，还是创作内容 | 按任务与主要对象重选区域结构，不沿用默认章节 |
| 所有内容等大、等亮、同样醒目 | 内容是否真的同等重要，是否存在不同紧急程度或操作职责 | 明确主对象与下一步操作，再调整尺度、顺序和强调程度 |
| 每块内容都有悬浮 Card，Card 里继续套 Card | 是否确有对象包含关系 | 保留必要对象边界，用分组间距、细线或背景层级替代装饰性嵌套 |
| 后台和工作台先出现巨大宣传文案 | 用户进入后需要完成什么 | 让搜索、筛选、状态、负责人、队列及实际操作先可见 |
| 更换风格后仍是相同导航、分栏 Hero 和 Card 网格 | 结构是否由真实任务决定，所选风格如何参与表达 | 保留任务骨架，改变有依据的构图、密度、字体和组件处理 |

## 视觉与组件

| 看到的现象 | 先判断什么 | 优先修正方向 |
|---|---|---|
| 页面到处使用强调色、发光或强对比边框 | 操作色、状态色和装饰色是否混用 | 按职责分配强调，让主要内容和状态更容易辨识 |
| 粗字、渐变、玻璃、纹理或大圆角大量出现 | 是否属于用户品牌或已选风格，是否损害可读性与层级 | 保留有依据的特征，降低无关区域的竞争；不把所有页面统一改成中性极简 |
| 多种无关风格共用相同 Button 和容器 | 风格差异是否只剩颜色 | 校准几何、材质、图标和实际状态，使控件属于同一产品 |
| 同类行、图标、数字或标签不对齐，间距忽大忽小 | 是否存在稳定尺度和真实的分组关系 | 优先复用项目尺度，统一同类对象的对齐与密度；允许有理由的光学校正 |
| 默认态精致，展开、选中、禁用或错误态突兀 | 组件实际支持哪些状态，是否使用了未设计的默认弹层 | 只补齐涉及的状态；按项目封装和控件契约统一外观及行为 |
| 每个指标都附带小图表、徽章或装饰图标 | 这些内容是否帮助理解变化或下一步行动 | 去掉重复装饰，保留必要数值、单位、比较依据及真正有用的趋势 |

## 文案与媒体

| 看到的现象 | 先判断什么 | 优先修正方向 |
|---|---|---|
| “下一代”“释放生产力”“强大洞察”等内容可套给任何产品 | 用户是谁，处理什么对象，能得到什么结果 | 使用真实对象、动作与结果；不发明功能或宣传承诺 |
| 数字、增长、客户证明缺少依据 | 来源、时间范围、比较对象是否明确 | 保留有依据的信息；缺失时说明不确定性，演示数据明确为示例 |
| 主操作只有气氛，没有结果 | 点击后实际发生什么 | 使用能预测结果的操作文案，并区分查看、选用、保存和提交 |
| 媒体只是抽象球体、设备样机或通用装饰 | 画面是否解释产品能力或用户对象 | 按[使用原则](usage-principles.md)选择能证明内容的产品画面、对象或素材；无必要时不加图 |
| 图片、图表和文字各讲各的故事 | 是否引用同一个对象、状态和数据 | 统一内容关系，选择最能支持主张的画面；不靠增加效果掩盖不一致 |

## 修正后的辨识度

检查具体对象、构图重点和识别细节是否来自该产品。仅换名称就适用于其他产品时，先补足内容与表达依据；稳定、熟悉的导航和可访问控件可以保留。产品专属细节应出现在有用的位置，不为凑齐风格特征而重复铺满页面。

按需从内容与结构、文案、间距与排版、配色与组件、媒体与动效这些层次推进；先解决导致问题的层次，再处理表现。修改后回看最初发现的具体问题及相邻区域，不以“更有设计感”代替复查结论。
